# Millennium (RNN) для JustMC

Порт RNN-части библиотеки Millennium (версия 5) из MX на код JustMC ([JMCC](https://github.com/Deolure/JMCC)).
Millennium 4.5 не переносился.

Перенесено: `RNNModelML` (checkData, learnByData, trainBatch, trainEpochs с подбором порога,
ROC/PR-AUC, лучшим чекпоинтом и final-fit), препроцессоры RAW / STATISTICAL / HYBRID,
StackedBiLSTM + LayerNorm, пулинги LAST / MEAN / MAX / ATTENTION, BinaryHead, AdamW,
формат весов `m1-rnn.dat` (через JSON).

Добавлено в порте: режим входа GRID (картинка построчно, строка на шаг), установка
нескольких моделей одним манифестом и файлы `{"store": ...}` с данными демо. На них сделаны
демо 2 — распознавание нарисованных цифр — и демо 3 — ИИ-собеседник на трёх языках: генеративная
чат-модель, которая при незнании отдаёт вопрос читателю Википедии.

## Установка

1. Залить нужный `.json` из `build/` на любой хостинг и загрузить в мир:
   ```
   /module loadUrl force <ссылка>
   ```
   затем `/play`.
2. Загрузить веса или создать новую модель:
   - `~ml model import <ссылка на quark-e.json>` — манифест, части скачаются сами
     (JustMC обрезает ответ сайта на 25000 символов, поэтому веса разбиты на файлы до 24000);
   - `~ml model reset` — случайные веса.
3. Проверка: `~ml selftest`. С весами quark-e должно быть `semantics ok: 1` и
   вероятность `0.942535907508501`.

## Демо 2: цифры

```
/module loadUrl force https://raw.githubusercontent.com/kireikosasha/MX-Project/master/justmc/build/millennium_digits_demo.json
/play
~dg install
~dg canvas
```

`~dg install` качает 10 моделей и сохраняет их как `digit0` … `digit9`. `~dg canvas` строит полотно
20 × 20 в 5 блоках перед игроком: белая стена и воздух перед ней. Рисуйте любыми блоками,
блок = 1, воздух = 0. Через секунду после последнего блока игрок получает титул с цифрой,
а в чат приходят вероятности всех десяти.

Размер и место цифры не важны: рисунок обрезается по рамке и вписывается в картинку 14 × 14
с сохранением пропорций, поэтому цифра 3 × 3 в углу и цифра во всё полотно читаются одинаково.

| Команда | |
|---|---|
| `~dg guess` | распознать сейчас |
| `~dg clear` | очистить полотно |
| `~dg status` | сколько моделей установлено, какой набор используется, где полотно |
| `~dg install` | скачать малый набор моделей (админы) |
| `~dg install huge` | скачать большой набор моделей (админы) |
| `~dg model small` / `~dg model huge` | каким набором распознавать (админы) |
| `~dg canvas` | полотно перед собой (админы) |
| `~dg corners x1 y1 z1 x2 y2 z2` | полотно по левому верхнему и правому нижнему углу, как их видит рисующий (админы) |
| `~dg auto` | автораспознавание вкл/выкл (админы) |

Полотно по умолчанию: от (9, 83, 10) до (-10, 64, 10), смотреть с севера (z < 10).
Меняется константами `DG_X1` … `DG_Z2` в `src/demo_digits.jc` или командами выше.

### Модели

Два набора по 10 моделей Millennium (по одной на цифру, «моя цифра или нет»): режим GRID,
BiLSTM + LayerNorm, attention, sigmoid-голова. Энкодер внутри набора общий, поэтому распознавание —
один проход LSTM и 10 голов. Каждая сохранённая модель при этом полноценная:
`~ml model load digit7` и обычный `ml_predict` дают вероятность семёрки. Можно поставить оба набора
и переключаться командой `~dg model`.

| | small (`~dg install`) | huge (`~dg install huge`) |
|---|---|---|
| папка | `weights/digits` | `weights/digits-huge` |
| имена в мире | `digit0` … `digit9` | `digithuge0` … `digithuge9` |
| BiLSTM | 32 | 48 |
| параметров на модель | ~12 тыс. | ~25 тыс. |
| действий на распознавание | ~60 тыс. | ~80 тыс. |
| датасет | 230 тыс., высота 3–20 блоков, ширина по шрифту | 395 тыс., плюс широкие и квадратные цифры до 20 × 20, крупные контуром |
| всего | 89.4% | 94.1% |
| пиксельные цифры | 92.3% | 98.5% |
| незнакомые шрифты | 83.8% | 87.2% |
| рукописные MNIST | 83.8% | 85.0% |
| до 8 блоков | 87.5% | 90.1% |
| от 15 блоков | 89.4% | 96.0% |
| от 15 блоков, квадратные (18 × 18, 20 × 20 ...) | 89.0% | 96.2% |

Обе колонки посчитаны на одной отложенной выборке от датасета huge (шрифты, которых не было
в обучении, тестовая часть MNIST, все размеры и пропорции).

Обучение (Python, PyTorch, прямой проход повторяет `ml_net.jc`):

```bash
python tools/digits/digits_data.py --fonts /usr/share/fonts <папка со шрифтами> --mnist <папка MNIST> --out data.npz --font-reps 100 --mnist-reps 3 --pixel-reps 1500
python tools/digits/digits_train.py --data data.npz --out weights/digits-huge --pack digithuge --hidden 48 --epochs 40 --batch 512 --lr 3e-3
```

Датасет huge: ~160 шрифтов (системные, рукописные и пиксельные Google Fonts), рукописные цифры MNIST
и пиксельные глифы 3 × 3, 3 × 4, 3 × 5, 5 × 7. Каждая картинка «рисуется блоками» в случайной рамке:
высота 3–20 блоков (мелкие, средние и крупные поровну), ширина свободная — узкие, широкие
и квадратные цифры до 20 × 20. Штрих часто утончается до одного блока, иногда кисть в 2 блока,
пиксельные глифы рисуются и крупным контуром из линий; плюс поворот, наклон и мелкие ошибки
рисования. Рваные обрывки и залитые кляксы отбрасываются. Нормализация та же, что в JustMC.

## Демо 3: ИИ-собеседник (чат + Википедия)

```
/module loadUrl force https://raw.githubusercontent.com/kireikosasha/MX-Project/master/justmc/build/millennium_reader_demo.json
/play
~ai install
~ai привет, как дела?
~ai кто написал «Войну и мир»?
```

`~ai <сообщение>` — на русском, украинском или английском. Отвечают две модели на Millennium:

- **чат-модель** (~6 млн параметров) сама пишет ответ токен за токеном, как GPT; в экшн-баре того, кто
  спросил, видно, как пишется ответ. Следующее сообщение того же игрока в течение 3 минут продолжает
  разговор: модель помнит предыдущий обмен репликами;
- если чат-модель «не знает» — первым токеном хочет выдать служебный `[W]` (так её учили на
  энциклопедических вопросах), — отвечает **читатель**: ищет в Википедии и пересказывает предложение
  с ответом. При P([W]) ≥ 0.4 отвечает только читатель (или честно «не знаю»); при 0.1–0.4 чат-модель
  сначала пишет свой ответ, и он идёт в чат, только если читатель ничего не нашёл.

Это эксперимент: модель маленькая, у неё характер дерзкого бота сервера, учена в том числе на живых
диалогах с матом, так что отвечает как придётся. Факты она не выдумывает только потому, что на
энциклопедические вопросы уходит в Википедию.

`~ai wiki <вопрос>` — сразу к читателю. `~ai install` качает обе модели (около тысячи файлов по ≤ 24000
байт, 10–15 минут); если читатель уже стоит, докачивается только чат. `~ai status` — что установлено.

### Чат-модель

| | |
|---|---|
| параметров | ~5.9 млн: эмбеддинги 19 754 × 256 (5.06 млн, 8 бит, общие для входа и выхода) + LSTM 256 (525 тыс.) + внимание, выход, классы (~290 тыс.) |
| словарь | свой WordPiece на 19 750 токенов, обучен на диалогах: на реплику уходит на ~15% меньше токенов, чем со словарём читателя |
| на токен в JustMC | ~15 тыс. действий, из них ~13 тыс. — шаг LSTM (≈50 действий на нейрон); ответ — обычно 15–30 с |
| установка | ~840 файлов, ~19 МБ; в мире — сохранённая модель `chat` и save-переменные `ch.*` |

Как устроена и почему именно так. JustMC тратит время на *действия*, а не на умножения: «Математическое
ожидание» по строке из 500 чисел стоит столько же, сколько по строке из 50. Поэтому число строк (нейронов
LSTM) небольшое, а сами строки длинные, и всё вокруг LSTM сделано в минимум действий:

1. **Вход.** Токен → строка из 256 символов его 8-битного эмбеддинга. У таблицы один масштаб, он вшит в веса
   при экспорте, поэтому в LSTM идут прямо коды символов (`text_to_chars`), без пересчёта в числа.
2. **LSTM библиотеки** (`ml_lstm_step`, 256 нейронов, LayerNorm; модель сохранена в мире как `chat`).
   Состояние после служебного `[U]` посчитано заранее — на шаг меньше.
3. **Внимание на сообщение.** Состояния LSTM на токенах сообщения запоминаются (ключ 64 числа, значение
   128); на каждом шаге ответа модель смотрит, какие слова сообщения сейчас важны.
4. **Выход** `o = Wp · [1 | h | коды токена | контекст]`: кроме состояния в него идёт сам предыдущий токен
   (короткая связь «слово → следующее слово») и прочитанный из сообщения контекст.
5. **Следующий токен в два шага:** класс (~170 классов по частоте, частые токены — в классе поодиночке),
   потом токен внутри класса. Классы подобраны так, чтобы на шаг приходилось минимум действий
   (в среднем ~46 кандидатов вместо 19 000). Повторы штрафуются.
6. **Как выбирается кандидат** (и класс, и токен; смотрятся 16 лучших):
   - *предсказуемость по Колмогорову–Смирнову:* расстояние вероятностей 8 лучших кандидатов от равномерного
     распределения (`max |эмпирическая cdf − эталонная|`, как в `ml_feature_kolmogorov`). Если оно ≥ 0.75,
     выбирать не из чего — берётся лучший кандидат сразу, без выборки;
   - *typical sampling (энтропия Шеннона):* иначе берутся кандидаты, чья информация `−ln p` ближе всего
     к энтропии распределения, пока их масса не достигнет 0.9, и из них выбирается один с весами
     `p^(1/температура)`. Так отсекаются и «слишком очевидные», и «слишком случайные» токены. Логарифмы
     не нужны: `|−ln p − H| = |d − Σ p·d|`, где `d` — логит минус лучший логит;
   - `~ai sampling topk` возвращает обычный top-k.
7. До `[E]` или 36 токенов. Экшн-бар показывает конец текста.

На подвыборке (3 эпохи, LSTM 128) внимание и короткая связь дали −5% перплексии; подача прочитанного
контекста обратно в LSTM дала +4% и убрана.

| Команда | |
|---|---|
| `~ai <сообщение>` | поговорить |
| `~ai wiki <вопрос>` | сразу искать в Википедии |
| `~ai status` / `~ai about` | что установлено / что это |
| `~ai install` | скачать модели (админы) |

**Обучение — одна команда** (нужны Python 3.10+, git, видеокарта NVIDIA; PyTorch с CUDA и
`pip install -r justmc/tools/requirements.txt`):

```bash
python justmc/tools/chat/run_all.py --work ../millennium-chat
```

Скрипт скачивает датасеты, собирает диалоги, переводит часть на русский и украинский, строит обучающие
последовательности, учит модель (8 эпох), дообучает на «своих» диалогах бота, экспортирует файлы в
`justmc/weights/chat`, коммитит и пушит их. Готовые шаги пропускаются, прерванное обучение продолжается
с последней эпохи — команду можно просто запустить ещё раз. После неё в мире — `~ai install`.
В репозитории лежит модель, обученная этой командой; до первого обучения там заглушка (одна короткая эпоха).
Модель поменьше и побыстрее: `--hidden 192`; без пуша: `--no-push`. Перевод сам пропускается, если не
запустился; для него скрипт ставит `transformers==4.46.3` (новые версии требуют PyTorch 2.6+).

Данные:
- `tools/chat/synthetic/` — диалоги, написанные специально для этого бота (характер, Minecraft, сервер):
  4 тыс. групп «8 формулировок сообщения × 6 ответов», 1.2 тыс. диалогов из двух обменов, 3.2 тыс.
  вопросов для Википедии, поровну на трёх языках (синтетические);
- DailyDialog, PersonaChat, everyday-conversations (английский), russian_dialogues (русский, как есть),
  их переводы Opus-MT на русский и украинский, украинская часть Aya; один и тот же ответ («не знаю», «да»)
  остаётся не больше 20 раз, чтобы модель не отвечала им на всё;
- вопросы SQuAD 2.0, SberQuAD, UA-SQuAD и шаблоны «что такое X / кто такой X» с ответом `[W]`.

`tools/chat/chat_ref.py` — тот же алгоритм генерации на экспортированных файлах; с температурой 0 модуль
JustMC пишет ровно тот же ответ (проверяется в симуляторе).

### Читатель (Википедия)

Читатель отвечает и сам: `~ai wiki <вопрос>`, а без установленной чат-модели — на любое сообщение.

Как читатель отвечает:

1. **Язык.** Есть і, ї, є, ґ или апостроф — украинский; ы, э, ъ, ё — русский; нет кириллицы — английский;
   иначе по служебным словам, которые есть только в одном из языков.
2. **Поиск.** Ключевые слова вопроса (без служебных) уходят в поиск Википедии этого языка
   (`generator=search`, 3 статьи, их вступления). Ничего не нашлось — повтор с `OR` между словами.
   Ответ не влез в 25000 символов — повтор со вступлениями, обрезанными до 1200 символов.
3. **Отбор.** Из текста статьи убираются `[…]` и скобки без цифр (транскрипции, названия на других
   языках), даты в скобках остаются. В каждой статье — предложение, где больше всего ключевых слов вопроса (слова
   сравниваются по первым 5 буквам), и второе по счёту; вместе не больше 56 токенов. Слишком длинное
   предложение — его окно из 56 токенов с наибольшим числом ключевых слов.
4. **Модель** (2.6 млн параметров):
   - словарь WordPiece на 20 000 токенов, общий для трёх языков;
   - эмбеддинги 128 чисел на токен, 8 бит: каждый токен — строка из 128 символов `U+0100 + код`
     в тексте save-переменной, плюс масштаб строки; проекция в 32 числа считается прямо по кодам
     символов (`text_to_chars`);
   - каждому токену текста — взвешенная сумма токенов вопроса (внимание по скалярному произведению)
     и 4 признака слова: то же слово есть в вопросе, та же основа, есть цифра, с заглавной;
   - BiLSTM библиотеки с LayerNorm (сохранённая модель `reader`, вход 68, скрытый слой 24) — один и тот
     же для вопроса и текста;
   - вопрос сжимается attention-пулингом библиотеки, из него — векторы начала и конца ответа
     и оценки «ответа нет»;
   - ответ — самый вероятный фрагмент до 12 токенов, от начала слова до конца слова.
5. **Паранойя.** Ответ принимается, только если его вероятность выше вероятности «ответа нет» и не
   ниже порога tau, и если в нём есть слово, которого нет в вопросе. Иначе читается следующая статья,
   а после трёх — «Не знаю».

| | |
|---|---|
| параметров | 2 586 803: эмбеддинги 20 000 × 128 (2.56 млн, 8 бит) + проекция, BiLSTM 24, головы (~27 тыс.) |
| установка | 288 файлов + манифест, 6.7 МБ; в мире — сохранённая модель `reader` и ~1150 save-переменных `rd.*` |
| действий JustMC | ~100–210 тыс. на прочитанную статью (вопрос считается один раз, статей до трёх) |
| span F1 (валидация, 8 бит) | 68.1: английский 59.6, русский 64.3, украинский 80.7 |
| при tau = 0.4 | отвечает на 34% вопросов (среди них и вопросы без ответа в тексте); в 81% ответов пересказанное предложение содержит верный ответ: английский 67%, русский 78%, украинский 89% |

Валидация — отложенные вопросы SQuAD 2.0, SberQuAD и UA-SQuAD с тем же отбором предложений и чисткой
скобок, что в JustMC. Половина английских вопросов SQuAD 2.0 специально не имеет ответа в тексте,
поэтому английский ниже.

Знания — из Википедии (CC BY-SA); модуль пересказывает её предложения без ссылок, источник указан
в `~ai about`.

Обучение (Python, PyTorch; прямой проход повторяет то, что делает JustMC, `tools/reader/reader_ref.py` —

python tools/reader/build_reader_data.py --raw <папка с датасетами> --out data --vocab 20000
python tools/reader/reader_train.py --data data/reader_data.npz --out out --hidden 24 --epochs 10

Датасеты: SQuAD 2.0 (`rajpurkar/squad_v2`, английский), SberQuAD (русский), UA-SQuAD (`HPLT/ua-squad`,

## Использование из своего кода

```ts
import "./ml_admin.jc";                  // или millennium.jc без команд

event<world_start> { ml_admin_boot(); }  // или ml_boot()

ml_dataset_add(a, b, 1);                 // сэмпл: два списка чисел и метка 1 / 0
ml_train_async(16);                      // trainEpochs в фоновом процессе
p = ml_predict(a, b);                    // вероятность класса 1
if (p.greater(ml_threshold())) { ... }
ml_learn(a, b, 1);                       // один шаг обучения (learnByData)
```

Для картинок есть режим GRID (`~ml param im GRID`, затем `~ml model reset`): список — картинка
строка за строкой, по `ml.in` значений в строке, каждая строка — шаг LSTM.

Для одного сигнала передавайте один список дважды. Значения ожидаются порядка ±100
(RAW делит на 100 и берёт tanh). При длине от 40 HYBRID считает статистические признаки
по окнам.

Модель хранится в save-переменных `ml.*` и переживает перезапуск мира.

## Перенос весов между JustMC и MX

```bash
python tools/ml_convert.py dat2json m1-rnn.dat weights/model.json         # MX -> манифест + части
python tools/ml_convert.py json2dat m1-rnn.dat "export/*.json"            # части из export -> plugins/MX/models/
python tools/ml_convert.py info "weights/model-*.json"
```

Манифест и части должны лежать в одной папке на хостинге: имена частей в манифесте
берутся относительно его адреса.

## Нагрузка

| Операция | Действий JustMC |
|---|---|
| проверка 150 поворотов | ~80 тыс. |
| forward + backward чанка из 150 | ~170 тыс. |
| шаг AdamW по 81 266 весам (раз на батч) | ~2 млн |

Тяжёлые части работают в процессах и уступают тик каждые `ml.budget` действий
(по умолчанию 4000), а также пока загрузка CPU мира выше `ml.cpu_max` (75%).
Для быстрых экспериментов можно уменьшить сеть: `ml.hid` = 16, `ml.layers` = 1, затем
`~ml model reset`.

## Особенности JustMC, которые учтены в коде

- Сложение, вычитание, умножение и деление округляют результат до 9 знаков после запятой,
  а `pow` и «Математическое ожидание» считают точно. Поэтому активации, LayerNorm, обратный
  проход и AdamW написаны через `mathematical_expectation` и `pow` (`mli_mul`, `mli_add2`,
  `mli_sub2`, `mli_inv` в `ml_base.jc`). Вывод совпадает с MX до ~1e-7, веса после шага
  обучения — до ~1e-5 (в симуляторе с таким же округлением).
- Список, записанный как `[переменная]`, хранит не число, а обёртку, которую
  «Математическое ожидание» не читает. Все списки собираются добавлением элементов
  (`mli_cons`).
- Ответ веб-запроса обрезается на 25000 символах: веса разбиты на файлы по 24000 с манифестом.
- `~ml selftest full` печатает 20 проб и трассировку прохода по стадиям; по ним видно, что именно
  сломалось, если сервер изменит поведение.
- Время уходит на действия, а не на арифметику внутри них: мир выполняет около 10 тысяч действий в секунду,
  и «Математическое ожидание» по списку из 500 чисел стоит как по списку из 50. Шаг LSTM — около 50
  действий на нейрон при любой длине строк весов, поэтому в чат-модели строки длинные (эмбеддинг 256),
  а нейронов 256; коды символов 8-битного эмбеддинга идут в строки весов как есть.
- Веб-запрос с любым своим заголовком (например, `User-Agent`) не уходит и не даёт ни ответа,
  ни ошибки, поэтому запросы к Википедии отправляются без заголовков.
- «Установить значение в словаре» разворачивает списки в ключе и значении (это массивы до 15
  элементов), поэтому список в словарь не положить: кэш проекций читателя хранится в локальных
  переменных `rpc.<id>`.
- JMCC превращает `\t` и `\r` в строке в буквы `t` и `r`; в регулярных выражениях они записаны
  как `\\t`, `\\r`. Цепочка `if … elif …` без `else`, после которой идёт код, не компилируется —
  в конце всегда есть `else`.
- Индексы «Обрезать текст» и «Найти подтекст» проверяются при старте мира (`~ai status` их
  показывает), код не зависит от того, с 0 или с 1 они считаются.

## Сборка

```bash
python tools/build.py --jmcc <папка JMCC>
```

`build.py` компилирует все модули (`--only demo_reader.jc` — один), проставляет функциям иконки и описания
(`tools/function_meta.py`) и проверяет результат (`tools/check_build.py`): каждая функция
должна помещаться в одну строку кода JustMC (43 блока), без ранних выходов и необработанных
вложенных выражений.
